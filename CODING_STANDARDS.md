# Coding standards

Reviewers apply these to every PR. Each rule is a judgement call that no linter makes; ruff, shellcheck and actionlint run in CI, and `tests/scripts/test_pins.py` checks rule 5's pins. shellcheck covers `scripts/`, `docker/` and, through actionlint, the workflows' `run:` steps. The shell in the README and `docs/` is checked by `tests/scripts/test_doc_shell.py` instead (README, "Tests"): gates fail closed, a `curl` that sends PUT, PATCH or DELETE uses `-f`, every `curl` the `-f` check accepts runs through the gates' fake `curl`, failure branches end in failure, and SQL takes its values as psql variables.

1. **Check the effective configuration.** Anything that validates configuration reads it as upstream will at runtime: the same sources, the same parsing (for example `value.lower() == "true"` with no strip), and the same defaults. The sources are the process environment, any `.env` upstream loads, and every value upstream stores per bank or per tenant (a bank's `config`, a tenant's `get_tenant_config()`), through every upstream path that reads or writes it: the config API, bank import and clone, and anything that runs before authentication. When a stored value can weaken a setting, pin the deployment-wide value upstream checks before it reads the stored one, and make the startup guard enforce the pin. Do not scrub stored data in a runbook: another writer puts it back. The test cites each upstream reader it mirrors.
2. **Bound every write that unauthenticated input can trigger.**
   - Limit it per client (an IPv4 address, or an IPv6 /64) and in total.
   - Record that the limit was reached.
   - Cap the memory that tracks clients. A full table must never reset into "allow all".
3. **Make reserved values unforgeable.** A sentinel stored beside client-supplied values uses a form client input cannot produce.
4. **Keep docs true to the code.** In the same PR, check every README row, code comment and config comment that states behaviour against the code it describes. When the PR deletes a file, block or feature, search the whole tree for each distinctive token its removed lines carry (a flag, path, filename or command, such as `RUN --mount`, `pins.txt` or `uv pip check`) and settle every hit; a guessed phrase list missed seven stale lines in PR #42 (PR #42 retro).
5. **Pin what runs.** Base and tool images by digest, actions by commit SHA, Python packages by hash, CI's tools and the image's pins alike. A new pin carries its version as a trailing comment.
6. **Make fakes honour the contract.** A fake for an external CLI applies the call's output-shaping flags (gh `--jq` through jq) or the test asserts the full argument list, so dropping or changing a flag turns a test red.
7. **Fail closed in every window.** For each step that restarts, redeploys or reconfigures the app (in code, scripts or runbooks), name the auth state during and after it. Anything that reopens access waits on a verified result (a completed deploy with the expected digest, a keyless 401), never on a queued action. A check that guards a destructive step reports failure when any part of it fails.
8. **Read a language with its own parser.** Code that inspects shell, Markdown or a CLI's options uses that language's parser or the tool's own output (`shfmt --to-json`, a CommonMark library, `curl --help all`), not a regex or a hand-written tokenizer.
9. **Name every state an interruption leaves.** A procedure that commits in steps (a script, a runbook, a migration) names the state each interruption leaves: during each wait, and before and after each commit. Its recovery covers each of those states, and its test drives each one. The procedure lives in one doc; others link to it rather than restate it.
